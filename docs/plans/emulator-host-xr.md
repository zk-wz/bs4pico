# E1：模拟器宿主/XR 回归与诊断

本轮轻量基础验收结果已归档；实际结果见 [本轮实验](../device-validation/2026-10-10-emulator-host-xr-e1/RESULT.md)，统一执行状态见 [项目状态](../STATUS.md)。本轮只针对现有x86_64 PICO客体及实际ARM64兼容应用路径，不接游戏/Wine/Steam，不安排真机。

2026-10-10 用户调整本轮范围为**轻量基础验收**：不执行30轮压测与六份重复成本对比；已启动的五轮基线保留结果，不重复加轮。后续仅补必要的 Home 两分支、真实按钮/支持侧输入与数据首次读取/正常恢复，不要求长轮次、资源累积或性能结论。

## 要回答的问题

现有 Spatial/Native XR 基线能否在补充生命周期、输入和诊断后稳定复现，并为后续 Windows 图形桥提供可观察的宿主契约？

[已有结果](../device-validation/2026-10-09-spatial-openxr/RESULT.md)支持五轮切换、部分恢复和模拟右侧输入，但未覆盖 Home 取消、进程死亡、双侧输入或长期切换。本计划是补测，不撤销已有证据。

## 入口与准备

- 复用 `prototypes/spatial-openxr/` 的 Activity 所有权交接、`xrprobe.cpp` 和私有文件协议；保留直接 Native 对照入口。
- `build-apk.sh`、`windows-tools.sh`、`verify-emulator.py` 的使用见 [构建说明](../build/README.md)；runner 已参数化显式 device，包含自动生命周期、人工 prepare/check 及受限成本场景。实现不等于运行通过，以独立矩阵为准。
- 本机配置沿用 [环境记录](../device-validation/WINDOWS_EMULATOR_VALIDATION.md)，不安装新工具链或修改共享环境。每次确认实际设备、APK、runtime、GPU、ABI和可用输入模式。
- 扩展日志至少关联 Activity/worker/session 身份、生命周期、帧序号和预测显示时间；帧日志采样输出，避免日志本身影响场景。

## 执行内容

| 实验 | 操作与检查 | 成功证据 |
|---|---|---|
| 旧基线回归 | 新输出目录运行现有五轮场景；人工确认管理窗口和真正双眼场景 | 新双眼提交、管理容器销毁、Back 正常释放、数据一致；不是背景截图或单纯进程存在 |
| Home 取消与确认 | CLI 打开系统确认框；用 Ask 请用户先取消，再独立测试确认退出/重开 | 取消后焦点与 actions 恢复；确认后 Surface/session 正常释放，重开数据保留 |
| 场景交接压力 | 本轮按用户要求不执行；runner 的显式 stress 入口保留作专项工具 | 未验证长轮次稳定性或资源无累积，不作为本轮基础验收前提 |
| 数据基础恢复 | 正常 Back/finish 后重开，核对首次 read；必要时单列一次受控冷条件恢复 | 首次读取旧提交值，不以最终文件代替；不增加后台终止、自然 LMK 等专项验证 |
| 模拟输入与空间 | 左右分别观察 profile、active、grip/aim flags、trigger变化；显示方向轴、地板、左右手不同颜色 | 实际支持的输入确实变化，pose 与画面方向一致；不可用侧写“不支持/未覆盖” |
| haptic 契约预检 | 新增 haptic action 后，仅在 runtime/profile 支持时调用 apply/stop 并检查返回值 | 只确认绑定/API/错误处理；模拟器无物理振动，不能记为体感通过 |
| 受限成本观察 | 本轮按用户要求不采六份成本对比；显式 cost 入口保留但未作为性能交付实跑 | CPU/GPU、显示FPS、资源趋势与真机性能不计本轮通过 |

进程死亡场景应优先使用后台进程终止机制并核实进程确已死亡；若只能 force-stop，单独命名“force-stop 后数据恢复”，不能代替系统内存回收恢复，也不能代替正常退出证据。原有脚本的 force-stop 只用于建立冷启动条件。

## 判定与后续

- 基础功能验收通过：已测切换没有回退，Home 取消/确认各有证据，真实按钮及实际支持的输入可用，正常释放和所测数据恢复正确。单项失败保留现场和日志，只验证修正所需路径，不重跑长轮次或用成功覆盖失败。
- 左控制器、重置朝向或 haptic 若模拟器不提供相应能力，单独标为未覆盖；其余已测项可独立出结论，不伪造 tracking 或补写真机任务。
- 性能采样只用于发现保留线程、等待和资源趋势，不作为通过所必需的 Space Pro 性能指标。窗口最小化/遮挡、主机负载和样本长度必须记录。
- 若新探针引发回退，先定位其影响；场景互斥和正常退出问题未解决时，不将该宿主版本作为 E4 桥接基线。

## 交付与范围

交付新增调试入口/检查脚本、单次实验 `RESULT.md`、输入支持清单、生命周期日志及必要校验值。证据放 `docs/device-validation/` 的新实验目录，大型产物放新的 `private/validation/` 子目录，遵守 [通用记录规则](../device-validation/README.md)。CLI 不能完成的空间交互由用户操作，不注入鼠标；截图仅按根授权临时借用精确窗口前台，用户切走优先，不持续前台；只停止本次启动的模拟器。

这些结果证明模拟器宿主行为，不证明真实双手 6DoF、摘戴/待机、Space Pro 模式兼容或长期热性能。全部实验只访问探针自己的数据。
