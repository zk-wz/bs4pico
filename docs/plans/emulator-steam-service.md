# E3：模拟器真实 Steam 服务探针

待实施验证计划；执行状态见 [项目状态](../STATUS.md)。使用自有最小客户端，不启动游戏，不伪造账号、所有权、DLC 或票据。

## 要回答的问题

能否在模拟器的 Android 应用约束内，将匹配 ABI 的 Windows Steamworks 客户端接到可获取、可审查的真实 Steam 服务，并让初始化、所有权查询和异步回调正确工作？

本仓库 `steam_api64.dll` 是 API 桥，不是登录服务。上游 `lsteamclient_a64.dll` 只重建 Windows 半边，Unix 半边和真实客户端来自 Linux Proton/Steam，见 [上游架构](../upstream/ARCHITECTURE.md#steam-steam_api64dll--lsteamclient_a64dll)。现有 `tools/smoketest.cpp` 只覆盖部分客户端接口，不足以证明完整 shim 初始化、DLC 或回调。

## 执行前提与能力门禁

- Windows 正向实验依赖 E2 的 PE/DLL/Unix-call 通过，使用实际可运行的匹配 ABI；通常是模拟器 x64 诊断客户端，不直接加载现有 ARM64 DLL。
- 先确认真实服务及其库的来源、版本、ELF ABI、bootstrap、依赖、登录方式和使用/分发许可。GameNative Bionic Steam 仅为 [待核查候选](../research/README.md#模拟器运行环境与-steam-候选)，不是已采用方案。
- 专有客户端/bootstrap 若只有 Android ARM64 版本且没有已证明的模拟器加载路径，本轮正向服务实验不可执行。只保留已测的诊断/负向结果和具体阻塞，不写“Steam 已通过”，不改用 stub/账号协议库替代真实 Steamworks 后端。
- 不依赖额外 PC 的远端 Steam 服务来满足本轮本地 Android 闭环；WSL/Linux对照可辅助定位，但必须单列，不能当模拟器结果。
- 如评估本仓库 shim，需先实现并验证匹配候选 Wine/客体 ABI 的诊断构建；若先使用合法准备的真实 SDK 客户端库，仅证明该对照路径，不宣称 ARM64 shim 已验证。

服务来源/ABI审计可在 E2 前做；负向运行测试也需要一个确能执行的客户端。尚无可直接运行的 Steam 探针脚本。

## 最小实验

| 实验 | 操作 | 判定 |
|---|---|---|
| S0：无后端 | 在隔离测试会话中不给客户端配置服务，调用真正初始化入口 | 明确失败且可诊断，无默认用户/所有权或假成功 |
| S1：真实初始化 | 用户在批准的交互中登录；运行完整 Steam API Init、接口获取和关闭 | 正确连接 pipe/global user，接口版本匹配；不能只看 DLL 加载或 SteamID |
| S2：只读授权 | 查询 Beat Saber AppID 620980 的订阅/安装上下文；将已有和未拥有内容与真实账号基线对照 | 实际结果与账号一致；AppID 环境变量不是授权证据。没有可验证样本的项标未覆盖 |
| S3：DLC | 对用户已拥有的 DLC和可明确确认未拥有的 DLC分别查询 | 已拥有与未拥有结果正确；无已拥有 DLC 样本则正向 DLC 未验证，不采购内容来补测 |
| S4：异步与回调 | 选择该服务支持的只读异步查询，记录 call handle、完成/失败及分发；检查 shutdown 后不再回调 | 回调结构布局、结果大小、释放和线程/寿命正确；不触发购买或修改账号数据 |
| S5：服务中断与重连 | 停止本次测试服务，检查客户端失败/恢复；按支持方式重新建立会话 | 服务缺失不静默返回成功，关闭无泄漏；明确测试的是断服务还是网络断连 |

初始化和授权分开判定；Steam Offline 缓存如参与结果须说明其来源与状态，不能把合法缓存等同于在线登录通过。无需更改防火墙/网络设置来制造断连。

## 安全与来源审查

账号登录/Steam Guard 由用户完成；Agent 不索取密码或票据。只记录是否登录、接口版本、查询类型、结果及去标识化错误信息，不公开 SteamID/昵称。票据、token、密码、会话缓存和含凭据日志不作为证据收集，也不进入 Git/APK。

第三方开放源码和专有资产分开审查。若候选 bootstrap 或所谓 DRM 组件无法核实来源/授权/行为，或需要绕过所有权校验，停止该候选；上游“可联网/可用 DLC”的说明不是本项目授权正确的证据。

## 交付与决策

交付真实服务依赖/许可清单、匹配 ABI 的最小客户端、脱敏检查日志与单次 `RESULT.md`，遵守 [记录规范](../device-validation/README.md)。只使用自有程序，不读取或修改 Beat Saber 原始副本。

- 正向闭环通过：S1/S2/S4/S5 有证据，S0 正确失败；S3 按样本报告覆盖，不用 Init 成功替代 DLC。
- 只有无后端失败测试、Web 登录、游戏库下载或 SteamID 查询：只能标部分诊断通过，不能标 Steam 接入完成。
- 无模拟器适用真实后端：保留阻塞报告，完整游戏接入不获准进入；E1/E2及不依赖 Steam 的 E4小探针仍可独立推进。

模拟器 x64服务闭环即使通过，也不证明纯 Windows ARM64 API 桥或 Space Pro 的服务部署成立；不改变无 root、单 APK、真实授权的产品目标。
