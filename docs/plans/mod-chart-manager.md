# D5：BSIPA、mod 与 Spatial 谱面管理

## 后续目标与首轮边界

本阶段在 [D1](game-runtime.md)～[D4](game-delivery.md)原版已经可玩之后执行。交付：Spatial 管理 mod 安装／启用配置和自定义谱面，BSIPA 真正注入 ARM64 游戏，选择的 mod 与谱面实际进入游戏；不是空白管理页面或 no-op 加载器。

首轮 D1 只落地 [共享契约](ARCHITECTURE.md#数据与后续扩展契约)中的 modsEnabled、modProfileId 和独立目录，默认不注入、不加载、不安装 mod。D5 不阻止原版菜单／歌曲交付，不扩展 LIV／混合现实录制或全社区／商店平台。进度只维护在 [STATUS](../STATUS.md)，执行顺序见 [ROADMAP](ROADMAP.md)。

mod／注入器／谱面支持与内容条目复用 [组件契约](COMPONENTS.md)的同一注册表和兼容性解析，不另建 mod 云目录／更新安全体系；广泛记录未来条目不要求 D1～D4 或 D5 首轮实现全社区功能。D4 拥有云发布、更新消费及安全恢复，D5 首先落实本地真实行为，后续在线交付仅在用户选择后扩展。

## 已有适配与代码落点

| 已有落点 | 后续直接使用／修改 |
|---|---|
| `src/doorstop/`、`build.sh` 的 doorstop 目标 | 上游已有 Windows ARM64 Doorstop／winhttp 注入构建，接 D1 实例安装与运行 DLL 优先级。 |
| `versions.env` 的 BSIPA／MonoMod 版本与摘要 | 当前上游 BSIPA 4.3.7 配套 MonoMod.Core 1.3.4 的 ARM64 ABI 支持；按目标游戏／实际 mod 版本锁定，不声称所有版本通用。 |
| `install/bs-arm64.sh` 的 mod 安装／恢复与 no-mods 规则 | 参考已知组件和安装变更；实现为产品工作副本事务，不能直接在 Android 调用 Frame 脚本。 |
| `prototypes/spatial-openxr/` 管理页面与 D1 实例存储 | 新增真实 mod 配置、导入／启用／卸载、谱面列表和启动模式，继续使用同一个 Spatial UI Activity。 |
| D1 runtimeSet、D2 资源／授权、D3 生命周期 | 保持版本、真实 Steam 服务和 XR 通路；mod 不另建一套 Wine、账号或图形设备。 |

[上游 BSIPA 资料](../upstream/ARCHITECTURE.md#mods-bsipa)是 Windows ARM64／Steam Frame 适配依据，不代表 Android 端已经通过；遇到实际注入或模组问题就在本阶段修复。

## 实例、配置与启动契约

- 沿用 GameInstance／LaunchRequest 的 `resolutionSnapshotRef`，mod profile 只保留 profileId、启用集合、安装变更与原版恢复点，并引用同一注册表中的组件／内容身份及其兼容性结果；目标游戏、runtimeSet、选定版本／来源／摘要／依赖随不可变 ResolutionSnapshot 解析锁定，不另复制一套兼容模型。不要复制账号、Steam 票据或运行时秘密进 profile。
- 使用独立 modded 工作实例或完整可回滚的工作实例事务；不可把任何 mod 或更新写入唯一原始副本。原版启动选择与 modded 配置明确区分。
- `modsEnabled=true` 只在实际兼容的注入组件和已提交配置齐备后可用；页面“启用”表示配置提交，只有游戏实际加载证据才表示“已加载”。
- mod／谱面变更在游戏退出后提交，下次启动生效；不在歌曲运行中替换程序集、patch、谱面或音频，不承诺未实现的热加载。
- 谱面记录内容摘要、来源、曲名／作者、难度、目标格式、文件引用和导入状态；收藏／排序等仅为本地管理数据，不与 Steam DLC 权益混合。
- 实施注入、谱面加载或在线来源功能时查当前主要文档、源码／upstream issue，并搜索既有候选之外的可行方案，比较实际 ARM64 ABI、性能、许可、维护及兼容性。重大模块边界／交付、隐私、维护或体验选择提供 2～5 个真实选项、证据与推荐集中 Ask，等待选择再落地，继续无关工作；既定默认／日常修正不重复询问。决策及重开条件写入现有 decisions，证据写入 STATUS，不开独立注入研究阶段。

## 实现顺序 1：接入真正 BSIPA 注入

1. 以原版可玩实例建立已校验恢复点，准备独立 modded work／配置；继续使用 D1 的实际 Unity／Mono 与真实 Steam 服务，保留一键选择原版启动的入口。
2. 获取合法来源的目标 BSIPA 包／注入程序集，构建并部署现有 ARM64 Doorstop `winhttp.dll` 和所需 MonoMod.Core；保留许可证与摘要，不混入 x64 原生 DLL。
3. 在 Android 实例安装事务中落地注入所需文件和配置，接 Wine DLL override／加载路径；禁用 mod 时恢复原版 loader 选择，不删除正版文件或强行加载 Doorstop。
4. 优先自行实现确定的组件安装／注入配置，不默认依赖仅 x86 的 IPA.exe／wine-mono 工具；如实际包确需其安装逻辑，移植该逻辑或隔离该安装辅助程序，游戏执行热路径仍保持 ARM64。
5. 启动真实游戏，确认 Doorstop 进入匹配的 Mono、IPA.Injector／BSIPA 初始化并加载选定组件；异常、版本不匹配或注入失败在页面和实际日志说明，不能仅以 winhttp 已放入目录宣布成功。
6. 处理 ARM64 trampoline、C++／managed 异常、线程与 MonoMod 运行时兼容问题；采用已确认的上游修复，不改变真实 Steam 所有权校验或绕过 BSIPA 授权检查。
7. 可见成果：同一管理入口可以选择原版／modded 启动，并能在真实游戏观察一个实际启用的兼容 mod 行为；原版路径仍正确。

## 实现顺序 2：可用的 mod 配置管理

1. 管理页读取同一组件注册表及实际安装清单／mod metadata，显示名称、版本、依赖、目标 Beat Saber 版本、交付来源、启用配置与最近加载结果；未知兼容性明确标未知，不给所有 managed DLL 默认绿灯，也不把禁用或未来目录条目画成可下载／可执行。
2. 首先支持用户选择合法 mod 包或本地目录的导入／启停／移除，不先建设完整在线 mod 商店。公开 metadata 或以后在线包交付属可选用户选择，研究当前来源与其他可行方案、比较许可／隐私／维护和体验并 Ask 后实施；复用 D4 的签名目录、允许的 installer／loader 与安全事务，不另建绕过策略的下载器。
3. 导入通过同一 typed installer 检查路径穿越、重名、依赖／冲突、合法来源、许可证和 native ABI；managed IL 跨 CPU 不等于其 P/Invoke 依赖兼容。只有 x64 native 实现的 mod 明确不可用于纯 ARM64 游戏，除非取得／构建对应 ARM64 版本；新安装能力尚未实现时显示需新版 APK，不执行未知包。
4. 依据选定 profile 通过共享解析器生成兼容 ResolutionSnapshot 和真实安装／启动事务，包含注入器、mod、谱面支持组件及内容；依赖无法满足则阻止启用并显示具体原因，不静默缺省组件造成假启用。
5. 改动前记录恢复点、变更清单与数据兼容性，完成 staging 后原子提交 profile／快照引用；取消／失败保留上一个可启动集合，回滚同时恢复匹配组件与兼容数据，不只退 DLL 而留下不可兼容存档。卸载只撤销该配置拥有的文件，不删除其他 mod 数据或用户存档。
6. mod 导致实际启动／XR 恢复失败时，提供用户可选的原版启动和回滚入口；不自动反复重启或以伪造加载成功隐藏问题。

## 实现顺序 3：Spatial 谱面管理到游戏加载

1. 支持导入用户有权使用的自定义谱面目录／包，读取目标游戏支持的 metadata 和文件引用；校验路径、音频／beatmap 必要文件、格式与内容摘要，失败说明具体项。
2. 内容写入实例的独立谱面存储，通过同一注册表记录内容身份／摘要／合法来源与格式能力，校验后随 profile／快照事务提交索引；相同内容复用已提交条目，不根据曲名覆盖其他谱面。导入／删除只影响自定义内容，不能替代付费 DLC 或伪造解锁。
3. 在 Spatial 页展示曲名、作者、难度、来源和已安装状态，提供选择、导入／删除及筛选；数据来自真实文件，不用示例列表作为交付。
4. 将已提交谱面配置接入游戏真实支持的加载路径；若目标格式需要额外谱面支持 mod，通过同一注册表／解析器选取与游戏版本、注入器和 runtimeSet 兼容的真实组件，并纳入该次不可变快照。不要仅凭目录存在就报告游戏已收录。
5. 游戏启动后观察所导入曲目真实出现在列表，能开始和完成击打／计分／音频；菜单元数据与游戏选择一致。遇到解析或同步问题修复实际格式／加载适配，不用原版曲目冒充自定义谱面成功。
6. 自定义曲目变更下次启动生效，保持游戏运行目录稳定；删除前展示将移除哪些本地内容，不触及正版歌曲、DLC、原件、备份或用户未授权目录。

## 随实现进行的轻量路径检查与完成条件

在上述功能实施时沿一次实际会话检查当前路径：Spatial 导入一个兼容 mod／配置 → modded 真实启动且观察其行为 → 导入一首用户有权使用的自定义谱面并实际游玩 → 正常返回 → 选择原版启动确认注入关闭。当前功能涉及的失败回滚或不兼容依赖各必要一次，不另设验证阶段，不追加 mod 大矩阵、压力、独立注入探针或新的环境／设备动作。

- 加载以游戏自身初始化／组件结果和可见行为为证据，不能用 UI 勾选、程序集复制、日志文件生成代替；未支持的 mod 明确说明，不能声称所有 PC mod 通用。
- 共享 D3 的真实 XR／音频／授权路径，只修复 mod 新引入的回退，不重测所有历史原型场景；模组临时测试只用独立工作实例。
- 默认 WSL 构建／静态检查，实际运行才用后台 CLI；不自动抢焦点或截图，确需人工 VR 交互时集中一次 Ask。
- 完成包含真实 BSIPA 注入、至少一个兼容 mod 的实际行为、可提交／回滚的配置、Spatial 谱面管理和一首真实自定义曲目可玩，同时原版仍可启动。只有预留字段、空页面或安装文件不算完成。
- 没有目标设备或可获取合法输入时继续完成可实现代码，准确保留未跑条件；不可替代加载能力无法实现时说明具体原因和尝试，由用户决定继续或停止，不交付假 loader。
