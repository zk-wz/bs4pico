# 开发路线

更新：2026-10-11。后续直接开发产品，在实现中调研、选型、验证和修正，不再先建设一套模拟器可行性探针。共同设计见 [产品架构](ARCHITECTURE.md)与 [组件／云清单契约](COMPONENTS.md)，当前进度只维护在 [STATUS](../STATUS.md)；本目录维护见 [AGENTS.md](AGENTS.md)。

## 当前目标

**先让正版 PC Beat Saber 1.44.1 在单 APK 内本地启动并真正可玩，再做 BSIPA、mod 与谱面管理。**

当前首选主链：Windows ARM64 Unity／Mono → GameNative Bionic ARM64 Wine／Proton 移植 → ARM64 DXVK → Android Native Vulkan／PICO OpenXR。候选不是封闭列表，开发时继续搜索其他可用方案，实质取舍用 Ask。Spatial UI Activity 是管理入口，Native OpenXR Activity 是游戏入口。LIV／混合现实录制不在产品范围。

## 按成果执行的 Plan

| 顺序 | 开发计划 | 用户能看到的成果 | 依赖与边界 |
|---|---|---|---|
| D1 | [游戏运行链与宿主](game-runtime.md) | Spatial 中导入正版文件、准备工作实例、启动真实 ARM64 Unity 引擎并查看真实启动结果／日志 | 复用现有 APK；落地 Bionic Wine、Player／Mono／DXVK；尚未接通 Steam／XR 时不称游戏可玩 |
| D2 | [Steam 账号、资源与运行服务](steam-integration.md) | 真实登录／Steam Guard、游戏库、本地导入或正版下载、真实游戏授权接入 | 对接 D1 实例与启动；下载页面不是 Steamworks 后端，已有文件无需强制重新下载 |
| D3 | [游戏 OpenXR 与音频闭环](game-openxr.md) | 真正双眼游戏菜单、头／双手控制、完成一首正版歌曲并正常返回 Spatial | 集成 D1 运行链与 D2 真实服务；图形／输入开发可与 D2 并行，不等待完整下载 UI |
| D4 | [原版产品交付与基本性能](game-delivery.md) | 可安装、可恢复／更新、日常启动可靠的原版游玩 APK | D1–D3 实际闭环；轻量基础验收与实际瓶颈优化，不默认压测 |
| D5（后续） | [BSIPA 与 mod／谱面管理](mod-chart-manager.md) | Spatial 中管理 mod 配置、自定义谱面，并在游戏中真正加载 | 原版可玩后执行；D1 仅保留数据／启动边界，不提前加载 mod |

D1–D4 是当前原版开发主线；D5 已规划但不作为原版交付的前置条件。按顺序执行各 Plan 内的实现任务，不需要每完成一段就返回可行性研究。并行工作只用于独立代码开发，不制造独立验证项目。

已有正版文件的最短可玩路径是 D1 → D2 的账号／真实服务任务 → D3；D2 的完整下载／更新体验随后补齐并接 D4，不阻止游戏桥实现。此时 D2 只算相应子任务完成，未实现的下载功能仍属于本系列交付范围，不标整份计划完成。

组件清单覆盖内置、用户输入、本地、系统拥有与未来远程项，唯一条目源为 [`component-catalog.json`](component-catalog.json)，不要求现在实现所有登记项。D1 先固定本地兼容组合与启动快照，D2 接真实 Steam 来源／配套服务，D3 保持 XR 热路径，D4 交付签名云清单与更新／恢复，D5 接 mod／谱面；云服务不作为 D1–D3 的前置条件。当前尚无已部署清单或可下载 release。


## 开发中如何验收

- 每阶段以新增实际页面或真实游戏路径为成果；构建只是交付的一部分，不用自有 PE／图形／Steam 探针替代游戏进展。
- 默认当前关键路径和必要边界各一次；已有原型不反复回归，失败只修复并确认受影响路径。长时间性能采样或循环压力仅按用户专项要求执行。
- 构建／静态检查在 WSL；没有运行需要就不开模拟器。需要设备时优先后台 CLI，不自动截图／抢焦点；确需人工操作才集中用 Ask 请求一次。操作规则统一见 [根约定](../../AGENTS.md)。
- 同进程 Wine／Android XR、驱动或服务出现实现问题时，在当前功能内调查修复和新的替代方案，不只选择计划预列备选；实质架构／技术取舍先用 Ask，批准后切换。不可替代能力确实无法实现时，交付具体失败与已尝试方案，供用户决定停止项目。不退回前置验证循环。
- 模拟器 x86_64、ARM 兼容翻译、上游 Frame 结果与 Space Pro 真机结论分别记录；没有真机时仍继续可构建开发，不伪造运行／性能通过。
- 正版原件保护、备份、凭据与许可边界不因开发方式改变而取消，见 [构建与备份](../build/README.md)。
